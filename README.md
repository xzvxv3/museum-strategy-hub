# Museum Flow
박물관 운영자용 대시보드 프로젝트

박물관 방문 데이터를 시각화하고, 관객 특성과 시설 간 연관성을 분석해 운영 전략 수립을 돕습니다.

## 실행 준비

Python 3.9 이상과 Node.js 22.12 이상인 LTS 버전을 설치하세요. Windows에서 Python 설치 시 **Add python.exe to PATH**를 선택하세요.

원본 데이터는 저장소에 포함하지 않습니다. 실행 전에 `data/` 폴더에 아래 패턴에 맞는 CSV를 각각 하나씩 직접 추가하세요. 임의의 CSV가 아닌 프로그램에서 요구하는 컬럼과 형식의 데이터여야 합니다.

- `*_FST_TBL.csv`: 일별 방문 데이터
- `*_SECD_TBL.csv`: 월별 시설 간 연관 데이터

백엔드 첫 실행 시 CSV를 검증하고 로컬 DB를 자동 생성합니다. CSV는 이후 서버 시작 시에도 필요합니다. 생성된 DB, 분석 보고서(`analysis/`), 내부 문서(`docs/`)는 저장소에서 제외합니다.

## Mac / Windows 실행 방법

GitHub에서 받은 ZIP은 먼저 압축을 풀고 CSV 두 개를 `data/`에 넣으세요.

아래 명령은 프로젝트 루트 폴더에서 실행합니다. 첫 설치에는 인터넷 연결이 필요합니다.

### Mac: 백엔드

```sh
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

### Windows: 백엔드 (PowerShell)

```powershell
py -3 -m venv backend/.venv
.\backend\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\backend\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

`py` 명령이 없고 `python --version`이 설치한 Python을 표시한다면 첫 명령의 `py -3` 대신 `python`을 사용하세요. 가상환경 활성화는 필요하지 않습니다.

### 프런트엔드 (Mac / Windows 공통)

별도 터미널을 프로젝트 루트 폴더에서 열고 실행하세요.

```sh
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Windows PowerShell에서 `npm.ps1` 실행 정책 오류가 나면 `npm` 대신 `npm.cmd`를 사용하세요.

브라우저에서 http://127.0.0.1:5173 에 접속합니다. 실행 중에는 터미널 두 개를 열어 두고, 종료할 때는 **각 터미널에서 Ctrl+C**를 누르세요. 이후 실행 시에는 가상환경 생성과 패키지 설치 명령을 생략하고 각 서버 실행 명령만 사용하면 됩니다. 의존성 파일이 바뀌면 패키지를 다시 설치하세요.

8000 또는 5173 포트를 다른 서버가 사용 중이면 기존 서버를 종료한 뒤 실행하세요. `.venv`와 `node_modules`는 운영체제 간 복사하지 말고 각 컴퓨터에서 설치하세요.

## 농업박물관 캡스톤 시연

로그인 화면에서 **농업박물관 운영자 화면 시작**을 선택하세요. 해당 계정에 처음 로그인하면 분석 기간을 **2025-01-01 ~ 2025-12-31 전체 기간**으로 설정하고 아래 공통 시연 자료를 생성합니다. 팀원은 이 소스를 내려받아 실행한 뒤 같은 계정으로 시작하면 동일한 초기 자료를 볼 수 있습니다. 실제 대시보드·추천 전략을 보려면 기존과 같이 원본 CSV와 백엔드가 필요합니다.

| 실제 전체 기간의 추천 전략 | 시연 실행 기간 | 상태 | 가상 분석 예시: 전후 각각 28일 |
| --- | --- | --- | --- |
| 최근 3개월 방문 감소 대응 | 2026-04-06 ~ 2026-04-19 | 완료 | 요일 보정 일평균 약 +24.1% |
| 평일 수요 중심 해설·체험 운영 검토 | 2026-11-12 ~ 2026-11-23 | 완료 | 요일 보정 일평균 약 +16.0% |
| 4월 집중 수요에 대비한 월별 운영안 | 2027-03-15 ~ 2027-04-04 | 준비 | 실행 전이므로 성과 없음 |

각 계획에는 담당 팀·목적·완료 기준·메모가 입력되어 있으며 완료 계획에는 가상 실행 결과도 들어 있습니다. 운영 캘린더에는 2026년 11월 23일 브리핑, 25일 안내물 점검, 27일 체험 재고 점검, 12월 1일 운영안 회의를 넣었습니다. `운영` 유형의 일정은 캘린더에서 관리하고 행사 분석 목록에는 표시하지 않습니다.

**행사 전후 분석**에서는 완료 계획 2개를 선택할 수 있습니다. 이 시연 계획의 방문 지표는 실제 기업 자료가 아닌 **명시된 가상 데이터**입니다. 화면 상단의 공통 안내, 접힌 계산 기준, CSV 파일명과 내용에 가상 자료임을 표시합니다. 실제 CSV·DuckDB를 바꾸지 않으며, 일반 행사와 다른 박물관의 실제 분석 API도 바꾸지 않습니다. 실제 전략 제안 근거와 가상 실행 성과를 혼동하지 마세요. 가상 변화율은 행사 효과나 인과관계의 입증이 아닙니다.

평일 해설·체험 시연 계획은 2026-11-12 ~ 2026-11-23으로 이동했습니다. 기존에 같은 시연 계획을 저장한 브라우저에도 `weekday-2026-11-12-v1` 날짜 갱신을 한 번 적용합니다. 해당 계획의 실행일·종료일·시연 실제 기간만 바꾸며 메모·담당자·다른 계획·등록 일정·필터는 유지합니다. 이후 사용자가 다시 바꾼 날짜는 재로그인 때 덮어쓰지 않습니다. 가상 시연 자료는 미래를 포함하는 기간도 표시할 수 있지만 일반 실제 행사에는 같은 예외를 적용하지 않습니다.

초기화는 `2026-11-capstone-v1` 버전에 대해 **농업박물관 계정에서 한 번만** 실행합니다. 해당 계정의 기존 계획·일정은 시연 자료로 교체하며, 교체 전 값은 브라우저의 `museum-flow-operator:농업박물관:before-2026-11-capstone-v1`에 보관합니다. 총괄·다른 박물관·원본 CSV는 교체하지 않습니다. 이후 같은 브라우저에서 작성·삭제한 내용과 필터는 새로고침·재로그인해도 유지합니다.

GitHub는 공통 **초기 자료와 생성 코드**를 공유합니다. 브라우저에서의 후속 수정은 각 브라우저에 저장되며 다른 팀원의 기기와 실시간 동기화되지는 않습니다. 새 초기 자료를 배포하려면 자료를 수정하고 초기화 버전을 의도적으로 변경해야 합니다. 브라우저 저장소를 비운 경우에는 최초 자료가 다시 생성됩니다.

- 계획·일정 원본: `frontend/src/agricultureCapstoneData.js`
- 실제 추천 전략의 제목·실행 방향 스냅샷: `frontend/src/agricultureCapstoneStrategies.json` (원본 CSV 미포함)
- 최초 로그인 준비: `frontend/src/agricultureCapstoneSeed.js`
- 일별 가상 자료·분석 계산: `frontend/src/agricultureCapstoneAnalysis.js`

검증은 `frontend`에서 `npm run test:capstone`, `npm run test:plans`, `npm run test:events`를 실행합니다. 두 서버가 실행 중이고 Playwright Chromium이 설치되어 있으면 `npm run test:capstone:browser`로 로그인·계획·일정·분석·CSV·재로그인을 검증할 수 있습니다. 테스트는 별도 브라우저를 사용하며 사용자의 실제 브라우저 저장소는 건드리지 않습니다.

## 추가 기능 수정본

시설 비교·행사 전후 분석·운영 캘린더를 추가했습니다. Windows 실행 파일과 상세 사용법은 [추가기능_사용안내.md](추가기능_사용안내.md)를 참고하세요. 이번 통합 ZIP은 GitHub 업로드용 소스 코드입니다. 기업 CSV는 포함하지 않습니다. 로컬 실행 시 별도로 받은 CSV 두 개를 data/에 넣으세요. 팀의 방문 패턴 군집·유사 박물관 그룹 기능도 유지했습니다.
